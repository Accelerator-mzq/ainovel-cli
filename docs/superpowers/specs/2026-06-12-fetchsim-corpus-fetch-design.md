# /fetchsim 网络语料获取 设计文档

日期：2026-06-12
状态：已与用户确认

## 背景与目标

仿写画像（`/simulate`）的语料目前完全靠用户手动把 `.txt/.md` 文件放进 `simulate/`（主画像）或 `simulate/personas/<作者名>/`（竞稿人格语料）。本功能在画像生成的上游补一步**半自动语料获取**：用户给作者名 + 若干 URL，系统抓取网页/txt 直链、提取正文、清洗为 UTF-8 语料文件落盘，提示用户检查后自行运行 `/simulate`。

设计期间已确认的范围决策：

- **半自动**：用户提供 URL，系统不做联网搜索（版权责任归于用户的 URL 选择）。
- **来源范围**：静态 HTML 页 + txt 直链。**不支持**需 JS 渲染/登录的站点（起点、晋江主站等），不引入浏览器内核。
- **落点**：`simulate/personas/<作者名>/`（按作者归档，服务竞稿人格画像）。
- **不自动串联** `/simulate`：抓取只落盘 + 输出摘要，留人工质量检查点，不白烧 LLM 调用。
- **正文提取路线**：引入 `go-shiori/go-readability`（方案 A），不自写启发式提取器（方案 B，调参/测试成本高），不用 LLM 清洗（方案 C，与人工检查点取向矛盾）。

## 1. 命令与交互

- 新命令 `/fetchsim <作者名> <url> [url...]`，仅空闲状态可用（同 `/simulate`）。
- 作者名做目录名校验：拒绝空名、路径分隔符、`..`、Windows 非法字符（`<>:"/\|?*` 及控制字符），防路径穿越。
- URL 仅接受 `http://` / `https://` scheme；每条 URL 独立处理，单条失败不中断其余。
- 复用 `internal/host/sim` 的事件通道模式：`RunFetch(ctx, root, author, urls) (<-chan Event, error)`，TUI 异步消费进度事件，交互形态与 `/simulate`、`/importsim` 一致。`root` 为 simulate 目录根，解析方式与 `/simulate` 相同。

## 2. 抓取与提取流水线（每条 URL）

1. **HTTP 抓取**：30s 超时；响应体 20MB 上限（超限报错跳过该条）；请求头携带常见浏览器 User-Agent（默认 Go UA 被很多站点 403）；跟随重定向（Go 默认上限 10 次）。
2. **按 Content-Type 分流**：
   - `text/html` → `golang.org/x/net/html/charset.NewReader` 自动处理编码（HTTP 头 charset / meta 标签 / BOM 探测）→ `go-shiori/go-readability` 提取正文 → 纯文本。
   - `text/plain` 或 URL 以 `.txt` 结尾 → 字节流先做 UTF-8 校验，失败则按 GB18030 解码（GBK 超集，覆盖国内站点几乎全部场景）。
   - 其他类型（PDF、图片等）→ 该条报错跳过，v1 不支持。
3. 统一输出 UTF-8 纯文本。

依赖变更：新增直接依赖 `go-shiori/go-readability`（MIT，依赖轻）；`golang.org/x/net`、`golang.org/x/text` 由间接转直接。

## 3. 文件命名与落盘

- 落盘目录 `simulate/personas/<作者名>/`，不存在则创建。
- 文件名 = `清洗后的页面标题（HTML）或 URL 文件名（txt 直链）` + `-<URL 短 hash>` + `.txt`。
  - 短 hash 取 URL 的 SHA-256 前 8 位十六进制。
  - 同一 URL 重抓 → 文件名确定 → 覆盖写；内容未变时 `/simulate` 的内容指纹增量自然跳过，不浪费 LLM 调用。
  - 不同 URL 同标题 → hash 不同，不冲突。
- 标题清洗：去 Windows 非法字符与首尾空白，限长（标题部分截至 60 字符）；标题为空时退化为 `untitled`。

## 4. 质量自检与摘要

落盘前对每篇做启发式质检，可疑项在摘要中标 ⚠ 警告，**不阻断落盘**（留给用户人工判断）：

| 检查项 | 阈值 | 含义 |
|---|---|---|
| 正文过短 | < 500 字符 | 可能提取失败只抓到页面壳 |
| 中文占比过低 | 中日韩字符 < 30% | 可能抓到导航/英文垃圾页 |
| 乱码占比超阈 | U+FFFD 占比 > 1% | 编码判断可能错了 |

全部 URL 处理完输出汇总：每条 URL → 成功/失败原因、提取字数、落盘文件名、警告项；末尾提示：

> 请检查 `simulate/personas/<作者名>/` 下语料质量，确认后运行 `/simulate` 生成画像。

## 5. 错误处理

- 单条 URL 的任何错误（网络、超时、超限、类型不支持、提取为空）只记入该条结果，不中断批次。
- 全部 URL 失败时命令以失败态结束并汇总各条原因。
- 落盘 IO 错误（目录创建失败等）属批次级错误，立即终止并报错。
- `ctx` 取消（用户中断）随时生效，已落盘文件保留。

## 6. 测试策略

- 单测全部走 `net/http/httptest` 本地伺服，不碰真实网络：
  - HTML 提取：UTF-8 页、GBK 页（meta charset）、无 charset 头页;
  - txt 直链：UTF-8、GB18030 两种编码;
  - 异常路径：超大响应截断、不支持的 Content-Type、4xx/5xx、超时、重定向跟随;
  - 安全：作者名路径穿越/非法字符拒绝;
  - 命名：标题清洗、限长、空标题退化、同 URL 覆盖、异 URL 同标题不冲突;
  - 质检：三项警告阈值各分支。
- 合并前对真实公开 URL 做一次冒烟 e2e，留证据（输出截图/日志）。

## 非目标（v1 明确不做）

- 联网搜索作者作品（全自动模式）。
- JS 渲染页面、需登录站点、反爬突破。
- PDF/EPUB 等富格式解析。
- 抓取后自动触发 `/simulate`。
